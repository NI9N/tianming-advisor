## 一、背景与目标

天命顾问 skill 已有五套解读框架：十神（`shishen.md`）、大运流年（`dayun-liunian.md`）、西洋星盘（`xingzuo.md`）、健壮性认知系统（`jianzhuang.md`）、国学决策框架（`guoxue.md`）。

紫微斗数引擎早在 `scripts/chart.js` 中就有输出（第三方 MIT 引擎 `dzcmemory-web/bazi-ziwei-skill` 的 passthrough），但一直未被解读层使用——排得出、读不了。

**目标**：把紫微接入解读层，让它与已有框架配合——尤其与用户的健壮性认知系统（根/风/叶、过拟合 vs 健壮）深度同构，读起来不突兀、不当第二套孤立术语堆。

**约束**：
- 不重写紫微引擎，只做解读层接入（引擎仍是 passthrough）。
- 新增 `references/ziwei.md` 必须脱敏，通用知识，不含用户个人数据。
- 输出模板保持五段式骨架，紫微作为加深「动根还是动叶」判断的第二视角，不抢戏。

## 二、核心设计：紫微 × 健壮性 深度同构

紫微斗数本来就是一个「领域地图」系统，与健壮性系统的对应关系是一一映射的，这是「不突兀」的关键——不是生造翻译，是同一套语言的两个版本：

| 紫微术语 | 健壮性语言 | 决策含义 |
|---------|-----------|---------|
| 十四主星 | **根**（基本盘/慢变量） | 这领域你天生是哪种打法，不管外在怎么变 |
| 十二宫 | 人生领域的拆解 | 钱/事业/出行/状态…各是一个领域 |
| 四化：禄 | 顺风叶（注入资源） | 可借势，但别把风当根 |
| 四化：权 | 加压的风 | 硬任务压身，接住但别硬扛成常态 |
| 四化：科 | 虚名叶（名分认可） | 好看，虚名≠基本盘 |
| 四化：忌 | **过拟合警报** | 这领域付出多回报慢，宜退一步守根 |
| 煞星（火星/铃星/擎羊/陀罗） | 根上有毛刺 | 做事带痛感，但能磨出韧性 |
| 地空/地劫 | 根上有空转风险 | 计划易落空，需务实落地对冲 |
| 左辅/右弼/天魁/天钺 | 根周围有帮手 | 健壮加分 |

**解读口诀**：主星=根、四化=风/叶、忌=过拟合警报。动这里是动根还是动叶？会不会过拟合？

## 三、问题 → 落宫映射表

紫微不摊开十二宫，而是按问题类型落宫——主宫深读、辅宫一句带过（最多 1 主宫 + 1 辅宫）。

| 问题类型 | 落宫（主） | 落宫（辅） |
|---------|-----------|-----------|
| 该不该转型 / 换轨道 / 做大事 | 命宫 | 官禄宫 |
| 钱 / 接单 / 变现 / 投资 | 财帛宫 | 福德宫 |
| 去远方 / 出差 / 旅游 / 搬家 | 迁移宫 | 疾厄宫 |
| 状态 / 休息 / 回血 / 健康 | 疾厄宫 | 福德宫 |
| 合作 / 合伙 / 朋友 / 人际 | 交友宫 | 兄弟宫 |
| 感情 / 正缘 / 婚姻 | 夫妻宫 | 福德宫 |
| 买房 / 资产 / 安家 | 田宅宫 | 财帛宫 |
| 学习 / 进修 / 证书 | 官禄宫 | 福德宫 |

## 四、实现落地

### 4.1 `references/ziwei.md`（新增，六节）

1. **问题→落宫映射表**——上表，含取宫原则。
2. **主星 = 根（基本盘）**——十四主星速查表（主星→基本盘→易过拟合点）+ 辅星速查（贵人/煞星/空亡/桃花）。
3. **四化 = 风/叶（引动）**——禄/权/科/忌 的健壮性翻译表。
4. **解读三步**——定位落宫 → 读根 → 看风 → 判断动根还是动叶。
5. **ziwei JSON 字段说明**——实测字段名（`gongs[].gong/dizhi/mainStars/auxStars/sihua/daXian{isCurrent}/liuNian/liuNianYear`、`wuXingJu`）。
6. **通用示例**——脱敏演示数据，示范怎么从 JSON 读出结论。

### 4.2 `SKILL.md` 接线

- **Step 1**：排盘输出补充说明——`bazi 用于十神/大运/流年，ziwei 用于紫微落宫（解读见 Step 3 的 ziwei.md）`。
- **Step 3**：解读框架「6 份规则」→「7 份规则」，新增 ziwei.md 条目。
- **② 自身匹配度**：新增「紫微落宫视角」——问题落在哪个领域（命/财/官/迁/福…），该领域主星=基本盘是什么，判断「这事踩不踩你的根」。
- **③ 风险点**：新增「紫微四化引动」——该落宫有忌（过拟合警报）还是有禄（顺风叶）？动这里是动根还是动叶？
- **七 风格**：新增「术语卫生」硬规则——报告中每个命理名词必须在同一语境配白话解释；背景条卡片的星曜由渲染脚本自动配 `星曜=白话` 小注，正文引用新名词前自查是否已翻译（用户反馈：「写了名词却不解释等于没写」）。

### 4.3 渲染管线（`render-decision.js` + `decision-report.html`）

- `render-decision.js` 顶部新增星曜词表 `STAR_GLOSS`（十四主星 + 常用辅星 → 白话，如 贪狼=才艺·社交·扩张、地空=计划易落空）+ `glossStars()` 自动生成简注。
- `deriveStrip` 新增四个字段：
  - `daxian`：当前大限（`daXian.isCurrent === true` 的宫）→ `起始-结束岁 · 宫名 · 主星`。
  - `daxian_note`：该宫主星的 `星曜=白话` 小注。
  - `liunian_gong`：当年流年命宫（`liuNianYear === 当前年` 的宫）→ `宫(地支) 主星 · 辅星 · 化忌`。
  - `liunian_gong_note`：该宫主星 + 前两颗辅星的 `星曜=白话` 小注。
- `buildFlat` 的 strip 字段列表同步加入四个字段。
- `decision-report.html` 命盘背景条由 6 卡扩为 8 卡，新增「紫微 · 当前大限」「流年命宫落」两卡，每卡带 `conf` 小字注行；头部「方式」改为 `八字+紫微+星盘+健壮性`；② 小节标题加 `× 紫微`。

### 4.4 `decision.json` 融合示例（本次实测算例）

本次咨询「辞职后应不应该先休息半个月去旅游」，紫微融合进三处：

- **timing**：点出正走贪狼大限（16-25 岁），才艺与社交扩张期——出门见人、开眼界是旺的，休息半月去旅游正落在这段顺风期。
- **match[3]·紫微落宫·迁移**：问题落迁移宫，主星天机+文昌、无四化 → 基本盘「出外靠脑子+文书」健壮、风平；但天机是动脑的，旅游纯放空会浪费这根，建议带点想法出门（踩点/见人/看市场）。
- **risk[1]**：2026 流年命宫落疾厄宫（午），紫微+地空 → 地空=计划「想得很美、落空」，休息这事尤其要定具体行程，别空转成焦虑。

## 五、数据来源与隐私

- 紫微输出来自 `scripts/chart.js` 的第三方引擎 passthrough（`ziwei: chart.ziwei || null`），本项目不承担排盘计算，只做解读。
- `references/ziwei.md` 为通用知识库，脱敏，不含出生信息或人格数据。
- 用户个人数据（出生日期/时辰/地点、人格档案）仍只在本地 `config.yaml`，不进入任何入库文件与报告。
